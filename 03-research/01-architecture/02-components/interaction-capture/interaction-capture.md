# Interaction Capture — Implementation Catalog

Candidate Adapter shapes for the Interaction Capture slot
([../../../../01-architecture/02-components/interaction-capture.md](../../../../01-architecture/02-components/interaction-capture.md)).

Two shapes cover complementary halves of the corpus. A factory that
wants both history and a future training set typically installs one
of each.

## Candidates

### TLS-terminating wire proxy

- **Type**: loopback HTTPS interceptor + per-invocation wrapper.
- **Capture layer**: `wire`.
- **Notes**: The only shape that sees the assembled system prompt,
  tool schemas, and the conversation as re-sent on each turn. CLI
  transcripts drop those. Capture is opt-in per invocation so the
  interceptor CA is trusted only by the wrapped child. Secret
  headers are scrubbed before write. A cwd denylist fails closed
  (run unproxied, write nothing). Session identity is not native
  to HTTPS; the wrapper must inject a correlation id (URL userinfo
  / `Proxy-Authorization`, or a session-envelope join).
- **Limits**: sees only traffic that went through the wrapper.
  Volume is large (every turn re-sends the conversation). Not a
  fill of [Audit & Observability].

### Native-transcript collector

- **Type**: timer-driven readers over each Dev Product's local
  session store.
- **Capture layer**: `transcript`.
- **Notes**: Covers sessions the wire never saw, and history that
  predates the proxy. One reader per CLI store. All records tagged
  `training_eligible: false`. Ingest MUST be idempotent (`dedupe_key`
  + per-source high-water mark) so re-runs and multi-machine ingest
  under one account do not duplicate.
- **Limits**: no reconstructable input half. Store formats drift
  without notice; an unknown shape must still land as a raw record
  rather than be dropped.

### Vendor conversation export

- **Type**: official account-data export from a model provider.
- **Capture layer**: `transcript`.
- **Notes**: Useful as a backfill of cloud-side history the local
  store never had. Consumer exports typically return conversation
  text, not the assembled API request, so they stay
  `training_eligible: false`. Retention windows are short and
  non-exportable training opt-in does not produce a user-owned
  corpus.
- **Limits**: not a substitute for either local Adapter.

## Declined as the slot fill

- **Factory audit backends** (Loki, OpenTelemetry, App Insights).
  Those fill [Audit & Observability]. They record that a call
  happened and what it cost; they do not hold conversation content
  or training-eligibility semantics.
- **Working-memory products** (Mem0, Zep, LangMem, Letta, and a
  Cognee Adapter on a dataset that is not the Spec Graph). Those
  fulfill [Working Memory] — active recall during execution, and
  the replacement for each Dev Product's native memory — not the
  immutable recording side. See
  [../working-memory/working-memory.md](../working-memory/working-memory.md).
