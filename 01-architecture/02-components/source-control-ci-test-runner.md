# Test runner (named sub-contract of Source Control + CI)

This is **not a component slot**. It is a named sub-contract owned by
[Source Control + CI]. Folding "testing" into "CI will handle it" without
runner properties is the thin guidance this contract replaces.

The [Ungameable Gate](../../04-standards/10-ungameable-gate/ungameable-gate.md)
standard states the *rules* a runner must enforce.
Kernel one-command detection is a *required property* of the runner, not
a second harness. The cross-agent review contract is also not the runner:
mechanical claims are review-time assertions; standing properties live in
the tree and run with no review payload.

## Purpose

Give every implementer a way to *have* a runner — one command that proves
a standing property in an implementer tree and in an isolated orchestrator
clone — without mandating a vendor.

## Contract

Any Adapter (or other runner) that fills this sub-contract MUST:

1. **One command.** A single invocation proves a standing property (pass
   or fail, no prose). Kernel one-command detection is this property, not
   a parallel harness.
2. **Clone-local.** The same command runs in an implementer's working
   tree and in an isolated orchestrator clone of that repository. It MUST
   NOT require a host review-payload directory or an implementer
   working-clone path.
3. **Three coverage classes.** One invocation can run standing checks for
   agent-config, a platform layer, and a product repository. A
   language-specific runner that can only see one of those classes does
   not fill the slot by itself.
4. **Write-scope separation.** Tests the implementing agent does not own.
   An implementing agent MUST NOT edit the gate that scores it in the
   same change; a constructed mixed change is refused. An implementing
   agent MUST NOT merge while that check is red.
5. **Spec-derived, not impl-derived.** Standing checks are derived from
   declared acceptance criteria, not reverse-engineered from the
   implementation (Ungameable Gate requirement 2).
6. **Held-out assertions.** The runner can execute checks the builder
   cannot see, so overfitting to the exposed suite is detectable.
7. **No corpus backfill.** Already-shipped behavior gets a standing test
   when a bug is found, not as a campaign that writes tests for every
   old feature.

The Adapter MUST NOT require a named vendor (pytest, Jest, xUnit, and so
on). A worked reference may exist and MUST be tagged example-not-mandate.

## Required Adapter metadata

In addition to the universal fields in
[the Adapter Pattern](../00-adapter-pattern/adapter-pattern.md) and the
[Source Control + CI] fields:

- `standing_runner_command` — the one command that proves a standing
  property (repository-relative).
- `standing_suite_path` — the in-tree declaration of what that command
  runs. Default: `.eposforge/standing-suite`.
- `held_out_supported` — whether hidden extra checks can be supplied
  (`true` / `false`).
- `example_not_mandate` — `true` for any reference implementation
  published from this repository. A `true` value forbids citing the
  reference as a required vendor.

## Boundaries

- **Is:** the slot the ungameable-gate rules run in.
- **Is not:** a new component. Do not add it to the component roster.
- **Is not:** kernel detection as a second harness. One-command
  detection is a required property here.
- **Is not:** the cross-agent review contract. Review claims are
  assertions recorded during a session; standing properties must run
  with no review payload.
- **Is not:** a mandate to backfill tests for already-shipped features.
- **Is not:** a mandate of pytest, Jest, xUnit, GNU make, or any other
  named vendor.
